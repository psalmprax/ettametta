# Phase 13-01: Luma Ray API Rewrite

## Goal

Replace the deprecated Luma Dream Machine endpoint with the current Luma
Ray API so the Luma engine actually works end-to-end with a real key —
no more silent 404 → Playwright fallback.

**What ships in one commit:**

* `PROVIDER_CONFIGS["luma"]` → `https://api.lumalabs.ai/v1` (Luma Ray, not
  `dream-machine/v1`)
* `_generate_luma` rewritten for the Ray payload schema
  (`model`, `aspect_ratio`, `loop`, `duration` as `"Ns"` string,
  `keyframes.frame0` for image-to-video) and Bearer auth
* `_poll_luma_job` rewritten for the new GET `/generations/{id}` response
  shape (`state: queued|dreaming|completed|failed`,
  `assets.video` on completion, `failure_reason` on failure)
* `LUMA_API_KEY` added to both `src/api/config/settings.py` and
  `src/services/video_engine/settings.py` so the API process and the
  Celery worker both see it
* `__init__` reads `LUMA_API_KEY` from `settings` (with `os.getenv`
  fallback for legacy envs) and `_get_api_key("luma")` returns it
* `LUMA_API_KEY=` documented in `.env.example`
* 21 unit tests in `tests/video_engine/test_luma_ray_rewrite.py` covering
  settings wiring, payload shape, keyframes, aspect fallback, poll
  states, immediate-completion path, and missing-key skip

- ✅ `PROVIDER_CONFIGS["luma"]["api_url"]` is `https://api.lumalabs.ai/v1`

- ✅ `_poll_luma_job` returns `{video_uri, metadata}` on `state == "completed"`

- ✅ `LUMA_API_KEY=` is documented in `.env.example`

## Rollback

Revert commit `f568a097`. No DB migration involved. The Luma Ray
endpoint is the current production Luma API, so rolling back puts the
engine back into the "always 404 → Playwright fallback" state.
