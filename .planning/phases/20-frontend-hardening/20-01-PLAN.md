# Phase 20: Frontend Hardening — PLAN 01

## Goal
Implement remaining frontend features: subscription management, audit logs, content moderation, PWA support, and GPU batching.

## Tasks

### T1: Cancel Subscription UI (`apps/dashboard/src/app/settings/subscription/page.tsx`)
- Subscription status display
- Cancel subscription flow with confirmation
- Downgrade/cancel options
- API integration with `src/services/payment/stripe_service.py`

### T2: Audit Logs UI (`apps/dashboard/src/app/admin/audit-logs/page.tsx`)
- Log viewer with filters (date, user, action, severity)
- Export to CSV
- Real-time log streaming via WebSocket
- Integration with `src/services/security/audit.py`

### T3: Content Moderation (`apps/dashboard/src/app/admin/moderation/page.tsx`)
- Content queue for admin review
- Approve/reject/flag actions
- Automated flagging rules
- API: `/api/v1/admin/moderation/*`

### T4: PWA / Offline Manifest
- `apps/dashboard/public/manifest.json` — PWA manifest
- `apps/dashboard/public/sw.js` — Service worker for offline caching
- Add to `layout.tsx` metadata
- Cache strategy: cache-first for static assets, network-first for API

### T5: GPU Task Batching (`src/services/video_engine/batch_processor.py`)
- Accumulate multiple small jobs into single GPU batch
- `BatchProcessor` class with queue management
- `process_batch(jobs: list[VideoJob]) -> list[Result]`
- Configurable batch size and timeout

## Success Criteria
1. User can cancel subscription from settings
2. Admin can view and filter audit logs
3. Admin can moderate flagged content
4. App works offline with cached static assets
5. GPU utilization improved via job batching
