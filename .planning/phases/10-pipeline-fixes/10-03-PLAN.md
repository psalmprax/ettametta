# Phase 10-03 — AnalysisReport Read-Side Endpoint

## Goal

Add a **read-only** endpoint that returns the persisted `AnalysisReport` (written
by the Celery task in 10-02) for a given `content_id`. This is the **public
contract the Transform → Video button needs** — the frontend should be able to
poll this endpoint after kicking off `/discovery/analyze` and pull the
structured `AnalysisReport` (not the raw Celery `AsyncResult` blob) when ready.

Today the only "analysis" endpoint is `GET /api/v1/discovery/{content_id}/analysis`
which is **write-side**: it auto-performs analysis if none exists. That conflates
read and write and is the wrong contract for a UI polling button. The new
endpoint at the cleaner path `/api/v1/discovery/analysis/{content_id}` is a
pure read that returns 404 if no report is persisted yet, so the UI can keep
polling until 200.

## Why it matters

- **Separation of concerns**: read and write are different contracts. The
  Transform button just needs to read what 10-02 wrote.
- **Public contract**: defines the stable shape the dashboard renders and the
  video job dispatcher (10-04) consumes.
- **404 semantics**: lets the UI implement natural "analyze in progress" UX
  (still 200 OK, keep polling) vs. "never analyzed" (404, show a CTA).
- **Type safety**: returns a Pydantic-validated `AnalysisReport` so the
  dashboard, dispatcher, and tests all see the same shape.

## Success Criteria

1. `GET /api/v1/discovery/analysis/{content_id}` returns:
   - `200 OK` with `{"data": <AnalysisReport>, "persisted_at": <iso8601>}` when
     `ContentCandidateDB.analysis_payload` is present and parses as a valid
     `AnalysisReport`.
   - `404 Not Found` with `{"detail": "No analysis persisted for content_id"}`
     when the row exists but `analysis_payload` is null.
   - `404 Not Found` with `{"detail": "Content not found: <id>"}` when the
     row does not exist at all.
2. Response shape is the same `AnalysisReport` JSON that the 10-02 task writes —
   no transformation, no schema drift.
3. Auth-gated: requires a logged-in user (same `get_current_user` dependency
   used elsewhere in `discovery.py`).
4. The endpoint never performs new analysis. It is a pure read.
5. Existing `GET /api/v1/discovery/{content_id}/analysis` (write-side) is
   unchanged — the two coexist; the new one is the read contract.
6. Unit tests cover: 200 with full payload, 404 no-row, 404 no-payload,
   200 with `persisted_at` derived from `ContentCandidateDB.analysis_persisted_at`
   when available (falling back to `analyzed_at`).
7. All existing 10-01 + 10-02 tests still pass.

## Tasks

### Task 1 — Add the read endpoint
- [ ] Add `GET /analysis/{content_id}` to `src/api/routes/discovery.py`
- [ ] Use the router prefix `/discovery` so the full path becomes
      `/api/v1/discovery/analysis/{content_id}` (matches the request).
- [ ] `db: AsyncSession = Depends(get_db)` + `current_user: UserDB = Depends(get_current_user)`.
- [ ] Look up `ContentCandidateDB` by `id == content_id`; 404 if missing.
- [ ] If `analysis_payload` is None → 404 with `detail="No analysis persisted for <id>"`.
- [ ] Else → `AnalysisReport.from_db_payload(content.analysis_payload)`;
      on `ValidationError`, return 404 with a logger.warning (so a
      partially-corrupt payload doesn't surface as a 500 to the UI).
- [ ] Return the standardized `success_response` envelope:
      `{"data": <report dict>, "persisted_at": <iso8601>}`.
- [ ] Use `content.analysis_persisted_at` if set, else fall back to
      `content.analyzed_at` (older rows won't have the 10-01 column).
