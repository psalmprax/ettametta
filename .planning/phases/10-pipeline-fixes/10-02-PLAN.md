# Phase 10-02: Celery Task Rewrite + LLM-Output Mapper

## Goal

Wire the existing `analyze_viral_pattern_task` (`src/services/discovery/tasks.py`) to:

1. Map the raw `ViralPattern` (or a richer LLM dict) → `AnalysisReport` via a new mapper.
2. Persist the resulting `AnalysisReport.to_db_payload()` to
   `ContentCandidateDB.analysis_payload` (and the denormalized columns
   `analysis_status`, `viral_score_velocity`, `recommended_style`,
   `analysis_task_id`, `analysis_persisted_at`).
3. Be gated by `ENABLE_PERSISTED_ANALYSIS` (default `False`) so we can flip
   the switch independently of the column presence (10-01) and the
   read-side (10-03).

When the flag is `False`, behavior must be **identical** to the pre-10-01
code path (return dict, no DB write). When the flag is `True`, the task
additionally writes to the DB and returns the same dict with the new
persistence fields populated.

## Files to change

| File | Change |
|------|--------|
| `src/services/discovery/schemas.py` | Add `AnalysisReport.from_llm_output()` classmethod and a free-function `llm_output_to_analysis_report()`. |
| `src/services/discovery/tasks.py` | Rewrite `analyze_viral_pattern_task`: call mapper, conditionally persist, return backward-compatible dict. |
| `tests/discovery/test_analysis_persistence.py` | Add tests: `from_llm_output` with minimal ViralPattern, with rich dict, missing-field defaults, validation errors; `analyze_viral_pattern_task` flag-on/flag-off behavior, DB write shape, failure mode. |

## Tasks

- [ ] T1. **Mapper** — `schemas.py`:
  - Add `AnalysisReport.from_llm_output(pattern: ViralPattern, candidate: ContentCandidate, *, raw: dict | None = None, raw_model_output: dict | None = None) -> AnalysisReport`.
  - Add `llm_output_to_analysis_report(pattern, candidate, *, raw=None) -> AnalysisReport` (thin wrapper for symmetry with the rest of the codebase).
  - Default rules:
    - `hook.first_3_seconds` ← `" ".join(pattern.style_keywords[:3])` or `"Visual hook"` if empty.
    - `hook.emotional_angle` ← `pattern.emotional_triggers[0]` or `"curiosity"`.
    - `hook.scroll_stopper` ← `pattern.hook_score >= 0.7`.
    - `pacing.bpm` ← `pattern.pacing_bpm` (default 120).
    - `pacing.cuts_per_minute` ← `round(bpm / 12.0, 2)` (sane heuristic).
    - `pacing.recommended_duration_s` ← `min(max(int(candidate.duration_seconds or 30), 5), 180)`.
    - `structure.arc` ← `["setup", "build", "payoff"]` if retention >= 0.5, else `["hook", "payoff"]`.
    - `structure.act_breaks` ← `[recommended_duration_s // 3, recommended_duration_s * 2 // 3]`.
    - `structure.retention_curve` ← `[1.0, 0.8, pattern.retention_estimate, 0.5]` (3-4 points).
    - `style.recommended_style` ← `pattern.style_keywords[0]` or `"educational"`.
    - `style.color_palette` ← `[]` (LLM can fill in via raw dict).
    - `style.music_genre` ← `None` (LLM fills in via raw).
    - `style.motion_graphics` ← `pattern.style_keywords[1:5]`.
    - `sentiment.overall` ← `"positive"` if hook_score >= 0.5 else `"neutral"`.
    - `sentiment.target_audience` ← `candidate.niche or "creators"`.
    - `sentiment.emotional_triggers` ← `pattern.emotional_triggers` (bounded to 20).
    - `summary` ← candidate.title (truncated to 200) or `"Viral pattern analysis"`.
    - `viral_score` ← `int(round(pattern.hook_score * 100))` clamped 0..100.
    - `confidence` ← `0.5 if fallback_id (e.g. "os_pattern") else 0.85`.
  - If `raw` is provided, **override** the derived values with anything it
    contains under canonical keys: `hook`, `pacing`, `structure`, `style`,
    `sentiment`, `summary`, `viral_score`, `confidence`. This is the
    extension point for a richer LLM prompt.
  - `raw_model_output` ← the `raw` dict (or the pattern.model_dump) if provided.

- [ ] T2. **Task rewrite** — `tasks.py`:
  - Import `ENABLE_PERSISTED_ANALYSIS` from `src.api.config.settings`.
  - In `analyze_viral_pattern_task`:
    1. Build `ContentCandidate` (existing).
    2. Run deconstructor → `pattern` (existing).
    3. Call `llm_output_to_analysis_report(pattern, candidate)` → `report`.
    4. If `ENABLE_PERSISTED_ANALYSIS`:
       - Open `async_session_factory()`.
       - SELECT `ContentCandidateDB` by `candidate.id` (FOR UPDATE).
       - If found: set `analysis_task_id=self.request.id`,
         `analysis_status=AnalysisStatus.COMPLETED.value`,
         `analysis_payload=report.to_db_payload()`,
         `analysis_persisted_at=now()`,
         `viral_score_velocity=report.viral_score_velocity()`,
         `recommended_style=report.recommended_style()`.
       - Commit.
    5. Return the same dict shape as before, **plus** `persisted: bool` and
       (if persisted) the task id + timestamp. Legacy callers (Celery
       `AsyncResult` checks) only need `status` + `pattern`.

- [ ] T3. **Tests** — `tests/discovery/test_analysis_persistence.py`:

## Acceptance

- `ENABLE_PERSISTED_ANALYSIS=False` (default) → behavior identical to
  pre-10-02: returns dict, no DB write, no schema change at runtime.
- `ENABLE_PERSISTED_ANALYSIS=True` → after the task runs,
  `ContentCandidateDB.analysis_payload` is a valid `to_db_payload()` dict
  that round-trips through `AnalysisReport.from_db_payload()`. The
  denormalized fields `viral_score_velocity` and `recommended_style` are
  populated.
- All 18 existing 10-01 tests pass.
- All new T3 tests pass.
- No regression in unrelated test suites (`tests/discovery/`).

## Rollback

- Set `ENABLE_PERSISTED_ANALYSIS=false` in env (default) → task reverts to
  in-memory return path.
- Migration from 10-01 is additive (nullable columns); no destructive
  rollback required.
