# Phase 10-05 — Frontend Wire + WebSocket Push

## Goal

Wire the discovery pipeline end-to-end in the frontend:
1. Replace 3-second Celery polling with WebSocket push for analysis completion
2. Use `GET /discovery/analysis/{content_id}` to read persisted AnalysisReport
3. Display rich analysis results in a new `AnalysisResultsCard.tsx`
4. Pass `content_id` to the Create Video endpoint alongside `task_id`

## Why it matters

- **UX**: Users currently wait for 3-second polling intervals. WebSocket push
  gives instant feedback when analysis completes.
- **Robustness**: Polling relies on the Celery result backend. Reading from the
  DB endpoint is more reliable (survives broker restarts, TTL expiry).
- **Visibility**: Users see the full AnalysisReport (hook, pacing, structure,
  style, sentiment, viral score) before deciding to create a video.

## Success Criteria

1. Analysis completion is pushed via WebSocket (no more 3s polling)
2. `AnalysisResultsCard` renders the full AnalysisReport
3. "Create Video" button passes `content_id` to the backend
4. Backward compatible: fallback polling still works if WebSocket disconnected
5. Existing tests pass, no regressions

## Tasks

### Task 1 — Backend: WebSocket notification on analysis persistence

- In `_persist_analysis_report`, after successful DB commit, publish
  `analysis_complete` event to Redis `job_updates` channel
- Use existing `notify_job_update_sync` utility
- Non-fatal — log warning if notification fails

### Task 2 — Frontend: AnalysisResultsCard component

- Display: viral_score, confidence, hook insights, pacing, structure arc,
  recommended_style, sentiment, summary
- "Create Video" button with content_id
- Loading/empty states
- Dark theme, glass-morphism style matching existing DesignCard

### Task 3 — Frontend: Wire WebSocket + read endpoint

- Use `useWebSocket` hook to connect to `/ws/jobs`
- Filter `analysis_complete` events by candidate_id
- When complete, fetch full report via `GET /discovery/analysis/{content_id}`
- Pass `content_id` in create-video API call
- Keep polling as fallback when WebSocket is disconnected
