# Phase 10-06 — E2E Smoke Test + Observability

## Goal

Close the Phase 10 quality loop with an end-to-end smoke test that verifies the
full Discovery → Analysis → Video Job pipeline end-to-end, and add observability
instrumentation so the pipeline's health is visible in Grafana.

## Why it matters

- **Confidence**: A single test that touches every layer (route → DB →
  AnalysisReport → Celery dispatch → job metadata) proves the pipeline works.
- **Observability**: A Prometheus counter makes it possible to answer "how many
  videos were created from analysis insights this week?" without grepping logs.
- **Regression guard**: Any future refactor that breaks the `analysis_snapshot`
  in job metadata will be caught by CI.

## Success Criteria

1. An E2E smoke test verifies the full mock pipeline:
   - AnalysisReport is read from a fake DB row
   - `_pack_analysis_data` builds both `pattern` and `analysis_report`
   - `download_and_process_task.delay` is called with `analysis_data`
   - `job_service.create_job` receives `analysis_snapshot` in `extra_metadata`
2. A Prometheus counter `analysis_to_video_pipeline_total` is incremented each
   time a video is created from analysis with a valid `analysis_snapshot`
3. The counter is exposed on the existing metrics endpoint (Prometheus registry)
4. All existing 62 discovery tests continue to pass
5. No new TypeScript or Python errors introduced
